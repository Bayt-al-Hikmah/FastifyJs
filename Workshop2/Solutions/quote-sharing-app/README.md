# Quote Sharing App (Workshop 2 Solution)

A complete **server-rendered quote sharing application** built with Fastify, TypeScript, and Handlebars. Visitors can add quotes, browse the newest additions, search by author, and review collection statistics — all without creating an account.

The application deliberately stores quotes **in memory**. Data survives page reloads but disappears when the server restarts. This keeps the focus on rendering, forms, validation, and CSRF protection rather than database setup. Workshop 3 replaces the in-memory store with PostgreSQL and Prisma.

### What You'll Learn

- **Server-side rendering:** Every page is complete HTML generated by Handlebars.
- **Shared layout and partials:** One document shell, one navbar, one footer, and a reusable quote card.
- **Form handling:** Parse `application/x-www-form-urlencoded` submissions with `@fastify/formbody`.
- **JSON Schema validation:** Validate form content by content type and re-render the form with inline errors.
- **Preserving user input:** Failed submissions retain the values the visitor typed.
- **CSRF protection:** Generate a token for each form and verify it before processing the submission.
- **Post/Redirect/Get:** Redirect after a successful submission so refreshing does not submit twice.
- **Search semantics:** Case-insensitive, exact author matching with a clear empty state.
- **In-memory state:** A small store class that computes statistics and view models.
- **Error pages:** Friendly `404` and `500` pages instead of raw stack traces.

### Getting Started

**1. Install Dependencies**

```bash
npm install
```

**2. Run the Application**

```bash
npm run dev
```

The server starts at `http://127.0.0.1:3000`. No database, `.env` file, or migration is required.

**3. Build for Production (optional)**

```bash
npm run build
npm start
```

The build writes JavaScript to `dist/`. Start the compiled server from the project directory so `views/` and `public/` resolve correctly.

### Exploring the Solution

| Page | URL | What to Explore |
|---|---|---|
| Homepage | `http://127.0.0.1:3000/` | Six seed quotes, the ten-newest rule, and the empty-state fallback. |
| Share form | `/share` | CSRF token, character limits, and the submission rules aside. |
| Search | `/search?author=Rumi` | Exact, case-insensitive matching. Try `rumi`. |
| Empty search | `/search?author=Unknown` | The `No quotes found for author.` message. |
| Dashboard | `/dashboard` | Total quotes, distinct authors, and quotes submitted this run. |
| Missing page | `/nope` | The custom `404` page. |

**Test validation.** Submit the share form with a two-character author or a blank quote. The form returns `400`, keeps your input, and shows a field-level message. The same schema accepts JSON if you post to `/share` with `Content-Type: application/json` — but a valid CSRF token is still required.

**Test CSRF.** Open the share page, view the HTML, and remove the `_csrf` field before submitting. Fastify rejects the request instead of storing a quote.

**Test Post/Redirect/Get.** After a successful submission the browser lands on `/share?submitted=1` with a confirmation banner. Refreshing that page does not create another quote.

**Watch the in-memory behaviour.** Submit a quote, restart the server, and reload the homepage. Your quote is gone and the six seed quotes return. That limitation is the motivation for the database work in Workshop 3.

The store centralises the rules:

```typescript
add(author: string, text: string): Quote
getNewest(limit: number): Quote[]
findByAuthor(author: string): Quote[]
getStats(): QuoteStats
```

Route handlers decide which data to load and which template to render. Templates only format what they receive. The quote card is included with:

```handlebars
{{> quote-card}}
```

Normal `{{expression}}` output is HTML-escaped, so quote text and author names cannot inject markup.

### Available Endpoints

| Method | Path | Purpose | Authentication |
|---|---|---|---|
| GET | `/` | Show the ten newest quotes. | None |
| GET | `/share` | Render the submission form with a fresh CSRF token. | None |
| POST | `/share` | Validate, verify CSRF, store the quote, and redirect. | CSRF token |
| GET | `/search` | Search quotes by exact author name (case-insensitive). | None |
| GET | `/dashboard` | Show collection statistics. | None |
| GET | `/static/*` | Serve the stylesheet, logo, and favicon. | None |

### Workshop Objective

By completing this solution, you should be able to combine Handlebars rendering, static assets, form parsing, JSON Schema validation, CSRF protection, and the Post/Redirect/Get pattern into one coherent server-rendered application — and explain why each layer exists.
